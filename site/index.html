Hairline is a semantic integration engine. It reads each branch as symbols, references, signatures and the concrete values a type admits — then reports where one branch's contract change meets another branch's new code.

The problem

Git reasons about lines. The interesting failures are not textual.

Two agents work on one repository at the same time. Each one changes a different file. Each one passes its own tests. The merge is clean, and the system is broken.

agent-a

  • changes a shared contract
  • its own tests pass

agent-b

  • changes a consumer of it
  • its own tests pass
└──────────── merge ────────────┘
git merge-tree — clean ✓
tsc --noEmit on the merged tree — clean ✓
the value no longer exists; the new branch is dead code ✗

The type check is not a safety net here

The consumer takes a string, not a Status. By the time the value arrives, the type system has widened it away — so the merged tree type-checks, and the branch simply becomes unreachable at runtime.

Attribution, at the time the pull request opens

A merge queue tells you that the head is red. Hairline tells you which branch removed the contract, which branch added the consumer, and at what position in each — before either branch reaches the queue.

Only fresh use sites count

An interaction is reported only when the consuming branch introduced or edited the use site. If the site already existed at the base, that branch is broken on its own and its own CI catches it. This is the main reason the negative fixtures stay silent.

What it detects

Seven analyzers, one ordered pair of branches at a time.

removed-definition

A deleted symbol, under new code

A symbol one branch deleted or un-exported, used by code the other branch added.

export-surface

A name that left the barrel

A module stopped exporting a name the other branch newly imports — including a barrel narrowing, where the declaration itself never changed.

literal-set-change

A value that no longer exists

A value removed from the admissible set of a type, still named by new code.

signature-change

A call that changed shape

A call signature changed under a new call site — including sync to async, where the new caller holds a Promise it never awaits.

member-change

A member that moved out of reach

A member changed under a new read or write: type, optionality, or public to private, readonly, static.

same-symbol

One contract, two states

Both branches left the same contract in different states.

behavioral-risk

A changed default, under new consumers

A changed default or constant under new consumers. A prompt, not a verdict — it refuses to fire without a value-level signal and caps itself at low confidence.

Anatomy of a finding

Evidence with file positions, on a named branch.

hairline explain <id> quotes the source at every evidence site, from each branch's own revision — so a reader settles the question from the code and not from the prose.

hairline explain 8a47418b --base main --branches agent-a agent-b 
[1/1] HIGH   agent-a removes "disabled" from Status (src/user.ts);
             agent-b adds code handling it
        literal-set-conflict  confidence: medium  id 8a47418b3ed1

        agent-a narrows Status (src/user.ts) so that "disabled" is no longer
        one of its values. agent-b adds 1 site that still names "disabled".
        That site is typed loosely enough that type-checking the merged tree
        would not report this — the code would simply become unreachable at
        runtime.

        Evidence
          agent-a  Status: literal "disabled" removed from the admissible set
                   src/user.ts:1:1
            - "active" | "disabled" | "suspended"
            + "active" | "suspended"
          agent-a  Also narrows 1 symbol(s) typed by it: User.status
          agent-b  New equality on "disabled" against status — type at the
                   site is string, so a type check cannot see this
                   src/render.ts:5:18

        Why this confidence
          The value is named in a module that imports the changed one, but the
          type at that site has been widened to a primitive. A type check of
          the merged tree would not flag it; whether the value still reaches
          this code is not decided here.

        Suggested check
          Check whether the branch handling "disabled" on agent-b can still be
          reached, and whether removing the value was intended.

How it works

Five stages. The working tree is never touched.

01

Snapshot

Each revision is read from git objects. HEAD and the working tree are asserted unchanged by test.

02

Index

A virtual ts.Program and a two-pass walk build symbols, references, imports and literal sets.

03

Diff

Each branch is diffed against the merge base into typed contract deltas.

04

Analyze

The analyzers run over one ordered pair of branches at a time.

05

Report

Findings carry evidence, severity, confidence, the rule behind it, and what to check.

stable identity

Symbol identity never uses line numbers

ts:src/user.ts#User.status@property survives reformatting and unrelated edits. Positions travel separately, as evidence.

language-agnostic core

Adding a language changes nothing else

The graph, change model, analyzers and reporters are written against SemanticIndex, never against TypeScript. Capabilities are declared, not inferred.

safety

Your repository is untrusted input

It never executes repository code, never writes to the repository, and never uses a network. Git is invoked with explicit argument vectors and no shell.

Honest positioning

What this does not do, first.

The failure mode that kills a pre-merge gate is noise, not misses. So the limits are published next to the results, and the incumbent baseline runs over the same fixtures on every evaluation.

Conceded

A merge queue running tsc --noEmit as a required check catches type-visible cross-branch breakage for free. On 9 of the 13 positive fixtures, Hairline adds attribution and timing, not detection. Textual conflict resolution belongs to Mergiraf, and Hairline does not compete with it.

Where it adds detection

4 of 13 are invisible to that baseline: a consumer whose type has been widened to string; a JavaScript consumer with no types; two branches leaving one contract in different states; a changed default argument with a byte-identical signature.

What it cannot do

It cannot decide whether a body change altered behaviour. No static analysis here establishes that. Hairline says likely and evidence that these changes interact — never proved incompatible. And 100% on hand-built fixtures is a statement about the fixtures: precision on data it did not author is unmeasured.

Quickstart

One runtime dependency. Three commands.

# Node ≥ 22.6, git ≥ 2.38
git clone https://github.com/arnavnemade1/hairline && cd hairline
npm install      # one runtime dependency: typescript
npm test
npm run build    # produces dist/, which bin/hairline.js runs
# report the conflicts between two concurrent branches
node bin/hairline.js analyze --base main --branches agent-a agent-b

# one finding in full, with the source quoted at every evidence site
node bin/hairline.js explain 8a47418b --base main --branches agent-a agent-b

# machine-readable, and what each analyzer looks for
node bin/hairline.js analyze --base main --branches agent-a agent-b --json
node bin/hairline.js analyzers
# the primary consumer is a CI step deciding whether to stop
- name: Hairline
  run: node bin/hairline.js analyze
          --base ${{ github.base_ref }}
          --branches ${{ github.head_ref }} other-agent-branch
          --min-confidence medium

Exit codes — the primary consumer is a CI step deciding whether to stop

0

analysis ran, nothing found at or above the threshold

1

findings reported

2

invalid usage

3

analysis could not complete — distinct from 0 on purpose, because a failure must never read as "nothing found"

Point it at two branches you are about to merge.

It never merges, never rewrites, never executes repository code, and never talks to the network. The worst case is that it finds nothing.
